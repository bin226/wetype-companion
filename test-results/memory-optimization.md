# 2026-10-04 内存与独立启动检查

保持用户配置：CC-CEDICT 开启，青简、个人、自定义关闭。旧版是已运行的进程，新版启动后约 8 秒取样；未做同运行时长、多轮或持续输入比较。

| 进程 | 旧版工作集 MB | 新版工作集 MB |
| --- | ---: | ---: |
| EXE 启动器 | 19.6 | 已合并到主程序 |
| PowerShell 界面 / 新 EXE 主程序 | 257.3 | 205.2 |
| Python OCR | 107.0 | 108.8 |
| 合计 | 383.9 | 314.0 |

快照合计下降约 70 MB / 18%。工作集是驻留物理内存；私有提交量是另一种指标，不能将二者相加。原始数据见 memory-before.json、memory-after.json。

新版进程树为 WeTypeCompanion.exe → python.exe，没有常驻 powershell.exe。仍使用系统 PowerShell 引擎程序集，尚非全 C# 实现。

第一轮未主动回收时，主程序工作集约 341 MB；增加启动末尾的一次性 GC 后约 205 MB。识别路径没有强制 GC。第一轮新版空闲 20 秒测得两个进程 CPU 增量约为零，不能由此推断连续输入的峰值开销。

验证通过：Test-Lexicon.ps1（词库优先级、格式、真实词库）；Test-RapidOcr.ps1（10 张真实截图、高亮、OCR 协议、置信度与查词）；Test-App.ps1（配置、自启动、词库切换、失败回滚、界面渲染）；独立 EXE 启动、OCR 子进程和限时退出。

Test-App.ps1 原先继承用户当前选项，CC-CEDICT 配置下第一项会失败；现显式设置测试初始选项。测试使用临时配置并恢复原自启动项。

进一步降低基础内存需要迁移常驻脚本逻辑，或优化 OCR 运行时。全 Python 方案的词库对象和 GUI 框架成本需要原型实测；Windows 界面、词库和轮询迁到 C#，暂保留 Python OCR，可逐步去掉 PowerShell 引擎。
